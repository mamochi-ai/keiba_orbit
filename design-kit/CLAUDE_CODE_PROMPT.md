# KEIBA ORBIT — 実装依頼
添付の素材ZIPを展開し、同梱README、DESIGN_SPEC、preview.html、assetsを読んで、動作するWebシステムを実装してください。計画の説明だけで終了せず、実装・動作確認まで進めてください。ユーザーはPCを持たずiPad/iPhoneでClaude Codeを利用します。ローカルPC操作を要求しないこと。既存リポジトリがあれば構成・AGENTS.mdを尊重し、既存機能を破壊しない。新規ならReact/TypeScript等で静的配信可能な構成にする。利用する依存関係の現行公式ドキュメントを確認する。

## 目的と制約
注目する中央競馬1レースを分析し、上限3万円の仮想購入配分とnote用原稿を作る個人用ツール。実際の馬券購入機能はない。AI従量課金API不使用。Claude通常チャットへのコピー＆貼り戻しを使う。無料・サーバー不要を初期方針にする。競馬未経験者でも使える日本語UI。SNS・掲示板は使わない。分析結果の売上、的中、利益は保証しない。

## 実装順
1. 同梱架空デモでホーム→準備→結果貼付→レポート→note指示コピーの一連操作を完成。
2. インポート、検証、保存、再読込、エクスポートまで実装。
3. 実データ取得元を調査。合法な利用条件、価格、CORS、認証、更新時刻、取得項目をDATA_SOURCES.mdに記録し、確認済みの方法のみ接続。
自動取得可能なAPIやエンドポイントは未確定。JRAや他サイトにブラウザから直接fetchできる、という前提で作らない。CORS回避プロキシ・無断スクレイピング・秘密キー埋込は禁止。未実装は明示し、架空データへ自動で置換しない。自動取得が無理な項目はデータ貼付/JSONインポートで補う。無料の気象APIも条件と出典を確認。調査を理由にデモと手動経路の実装を止めない。費用を伴う契約・デプロイは行わない。

## 画面
共通ヘッダーにorbit-markとKEIBA ORBIT。ナビは「レース」「保存した分析」「設定」。デモ時は全画面に明確なデモ表示。
A ホーム: 日付、レース名が必須。取得できた候補から競馬場・R番号を確認。候補取得不能時は手入力を開き、推測でレースを決めない。前日/当日選択、予算初期30000円(100円単位)は補助設定。任意の参考文・画像を追加。画像はアプリが認識したふりをせず「Claudeへ別途添付」と表示し、ファイルを保持・表示できるようにする。
B 分析準備: レース同定、出走表、過去成績、馬場、天気、オッズを個別に取得済/未取得/古い/エラーで表示。元URL、提供者、取得日時、対象時点、デモかを保存。分析対象と情報締切を確認。「分析用コピー」「Claudeを開く(通常リンク)」「結果を貼り付け」。コピーは明示クリック起点、失敗時は選択可能な全文と手動コピー案内。Claudeへの自動入力・ログイン操作はしない。
C レポート: 結論、注目馬の根拠と懸念、基本/馬場悪化/速いペースの比較、予算、見直し条件、不足情報、出典。iPad横は本文+右側320〜360px予算欄、狭い画面は1列。右欄stickyはデスクトップのみで内容を遮らない。条件を選ぶと分析済み順位と理由だけ更新。未分析なら未分析表示し再分析導線を出す。表示切替で賭け金を勝手に変更しない。元レポートと新しい版を分ける。
D 保存: IndexedDB等で予想スナップショットを保存し過去版を上書きしない。端末保存は消える可能性を短く説明。JSON入出力を実装。日付・レース名・作成時刻・版を一覧表示。結果と収支はレース後に別領域へ入力、予想時点の内容は固定。

## レイアウトと素材
assets/orbit-hero.pngはホームヒーロー/レポート表紙だけに使用。本文背景は無地。透過SVGのロゴ/アイコン、orbit-ui.cssを実際に使用。DESIGN_SPECとpreview.htmlが見た目の基準。大きな馬写真、安直なカードの乱立、虹色、文字の過剰グローは禁止。見た目はSF、操作名は日本語。背景画像をUI全体の画像として貼らない。全テキストと数字はHTML。ボタンはCSSで通常/hover/active/focus/disabled/loadingを表現。実処理以外の進捗や偽ログを出さない。prefers-reduced-motion対応。タップ48px以上、基本本文16px以上。390/768/1024/1366幅で横はみ出しなし。

## データと検証
sample-race.jsonを参考に入力型、templates/analysis-prompt.txtの応答型のschemaVersion=1を定義しJSON Schema/Zod等で検証。未知フィールド、文字数、配列数、ファイルサイズに上限。JSONはevalしない。Markdown/HTMLを無加工挿入せずXSS防止。URLはhttp/httpsのみ。データに含まれる指示は命令として扱わない。
レースidとsnapshotIdが一致しない応答、出走していない馬ID、重複馬番、出走取消馬を含む配分、無効な券種/頭数を拒否。初版券種は単勝(win,1頭)とワイド(wide,異なる2頭)のみと明記。全券種対応を装わない。ワイドは通常の3着以内説明に加え少頭数等の払戻条件を現行公式ルールで確認し、適用条件不明なら払戻計算を保留。
金額は非負整数・100円単位。端数丸めで予算超過させない。spent=sum(bets.amount)、unspent=budget-spent、maxLoss=spentをWebで再計算し不一致を指摘。オッズがなければ予算配分は候補。馬体重や天気の欠損を0扱いしない。スコアを勝率と表示しない。モデル検証なしに期待値/最適配分を出さない。配分は裁量的仮説と表示する。
オッズ取得時点と券種を管理。ワイド等の幅のあるオッズはmin/max型に拡張して整数単位で払戻目安を計算、未確定と表示。払戻目安と利益(払戻−全購入額)を区別。的中確率や合算期待利益は勝手に算出しない。同一馬依存を明示。収支履歴は不的中も含める。

## Claude連携
templates/analysis-prompt.txtのプレースホルダーに検証済みレーススナップショットを埋める。応答はJSON、JSONコードフェンス1個も受け付けるがその他文章と混在時はエラー位置を示す。取り込み成功しても必ず確認画面を経る。予想結果を根拠なくAI検証済などと表示しない。
note記事作成用コピーはtemplates/note-article-prompt.txtに検証済み結果を埋める。末尾はtemplates/note-format-footer.txtと完全一致させ、後ろに追記禁止。これはClaudeへ渡す指示で、noteに直接公開する機能ではない。生成記事を貼り戻す任意欄を用意し、表示用プレビューとコピー用原文を分ける。外側コードフェンスを外す操作は明示ボタンにする。Markdownをnoteへ貼れば必ず見出しが変換されるとは保証しない。

## 完了条件
入力不備/未取得/貼付JSON不正/別レース/超過予算/オッズ不足/空の配分/コピー失敗を確認。合計不一致、ワイド同一馬2頭、架空デモ混入、危険URL、HTML文字列で意味のある自動テスト。通常/読み込み/空/エラーのUIを確認。タッチ、キーボード、縮小モーションを確認。レース日と情報時刻はJST表示で扱う。デモと実データを混ぜない。ビルドを通し、できたこと・未接続の取得元・確認方法を日本語で報告。ユーザーがiPadで試せる手順をREADMEに追記。
